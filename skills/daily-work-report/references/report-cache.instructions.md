# 日报与周报缓存规则

## 一、生成日报

1. 使用中文输出日报。
2. 按项目分组输出，每个项目独立编号。
3. 生成完成后，把最终日报追加写入 `C:\Users\lhq\.codex\memories\daily-report-cache.md`。
4. 按周次、日期、项目分层缓存：
   - 周次格式：`## 2026-W13`
   - 日期格式：`### 2026-03-24`
   - 项目格式：`#### 项目名称`
5. 每个项目的条目在该项目标题下独立编号，从 1 开始。
6. 同一天在不同工作区分别触发日报时，各自只写当前项目的内容，追加到对应日期的项目标题下，不覆盖其他项目已缓存的内容。
7. 输出日报时，读取缓存中当天所有项目的日报，与当前项目合并后一起输出，不只输出当前项目。
8. 只缓存最终日报内容，不缓存分析过程。

## 二、总结周报

1. 先读取 `C:\Users\lhq\.codex\memories\daily-report-cache.md`。
2. 默认汇总当前周，除非用户明确指定周次。
3. 只能基于缓存日报生成周报，不补充虚构内容。
4. 必须输出两份格式不同的独立周报，不能混写。
5. **第一份周报**必须使用 `1. 2. 3.` 这种英文点号编号格式，不得使用 `1、2、3、`。
6. 第一份周报每一条的格式统一为 `1. xxxx【李涵祺】`。
7. 第一份周报的每一条末尾都要追加 `【李涵祺】`。
8. **第二份周报**必须包含两个字段：`本周工作内容总结：` 和 `本周工作内容细则：`。
9. 第二份周报中的 `本周工作内容总结` 必须是概括性总结，不要逐条罗列明细。
10. 第二份周报中的 `本周工作内容细则` 再写相对完整的具体工作内容，按项目分组，项目名直接作为标题（如 `sbp-di-sdk-node：`），不加"方向"二字。
11. 第二份周报不要在每条后面追加 `【李涵祺】`，除非用户额外说明。
12. 最终输出不要出现英文。
13. 总结完成后不要自动删除缓存，只有用户明确要求时才删除。
14. 如果缓存文件不存在或已被手动清空，视为当前没有缓存，不要自动恢复旧内容。

## 三、删除缓存

1. 只删除用户指定的周记录或日期记录。
2. 如果用户没有说清楚删除范围，先询问再删除。

## 四、输出示例

### 第一份周报示例

```
1. 完成华能 portal 注册页 UI 重做与表单逻辑拆分【李涵祺】
2. 完成 axios 封装层统一拦截 code 与错误 toast 处理【李涵祺】
3. 完成 RSA 加密工具收口至 utils/crypto.ts，公钥迁移至 .env【李涵祺】
```

### 第二份周报示例

```

本周工作内容细则：
华能 portal：
1、注册页 UI 重做：深色玻璃卡片、两栏分组、字段提示等细节调整。

4、加密工具迁移到 utils/crypto.ts，注册 / 登录公钥从 .env 注入。
```
